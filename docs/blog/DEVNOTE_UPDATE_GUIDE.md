# 개발노트·기존 글 갱신 안내

이 폴더에는 티스토리 공개 글을 대조한 post-map, [근거 대조표](EVIDENCE_REGISTER.md), Markdown 원고, 티스토리 본문 HTML과 글별 metadata가 있습니다. 실제 공개 여부와 URL은 `post-map.json`의 검증 상태를 따릅니다.

## 이번 공개 글 조사

2026-09-24 KST에 공개 RSS, 사이트맵, 홈 및 실제 `/2`, `/3` 본문을 확인했습니다. 초기 조사에서는 게시글 2건과 정책 페이지가 나타났습니다. `/2`는 변경하지 않았고, `/3`은 2026-09-19 기준 v0.9d 문장을 보존한 채 v1.0/v1.2 현재 안내를 덧붙였습니다. 이후 개발노트 7편을 공개해 관리 목록의 게시글은 9건입니다.

공개 RSS·사이트맵은 비공개 글의 본문을 확인하는 수단이 아닙니다. 기존 `/3` 수정 전 관리 편집기의 현재 제목·본문·카테고리·태그·공개 상태를 다시 읽고 원문을 Git이 무시하는 로컬 위치에 백업했습니다. 공개 원문과 편집기 HTML이 항상 같다고 가정하지 마세요.

## 상태와 진행 순서

- `draft_ready`: Markdown·HTML·metadata 초안이 준비됨. 관리자 편집에 반영되지 않음.
- `saved_draft`: 편집기 임시저장이 실제로 확인됨.
- `published_verified`: 신규 공개 URL과 핵심 본문·링크가 열린 페이지에서 확인됨.
- `updated_verified`: 기존 URL에 수정한 내용이 저장되고 공개 화면에서 확인됨.
- `publish_unverified`: 게시/저장 요청은 했으나 원격 상태 검증이 끝나지 않음.
- `no_change`: 기존 공개 글이 최신이고 이번에 반영할 변경이 없음.
- `blocked`: 근거, 권한, 배포 상태 등 선결 조건 때문에 처리할 수 없음.

1. `post-map.json`에서 대상 글·처리 방식·실제 URL을 확인합니다.
2. 글별 metadata의 `evidenceUrls`, `sourceBaseCommit`, `sourceHeadCommit`, 공개/미검증 범위와 publish gate를 대조합니다.
3. 한글 패치의 사용자 적용 링크가 해당 포털 웹 패처인지 확인합니다. ZIP·BPS 직접 다운로드와 ROM 링크는 추가하지 않습니다.
4. 기존 글 수정이면 편집기에서 최신 본문을 다시 읽고 백업합니다. 이 폴더의 `/3` HTML은 기존 본문 전체가 아닌 **추가 삽입 조각**입니다.
5. 편집 후 실제 저장·공개 상태와 URL을 확인한 뒤에만 `postId`, 실제 URL, `publishedThroughCommit`, 본문 지문을 갱신합니다. 글 주소를 추정하거나 미래 URL을 미리 등록하지 않습니다.

## 게시 때 확인한 선결 조건

- 나리키리 던전2 v1.0 / 던전3 v1.2 노트와 `/3` 가이드 보완: 배포된 포털 웹 패처에서 해당 버전이 실제 선택 가능한지 확인합니다.
- 프로젝트 포털 개발노트: 공개 홈에서 프로젝트 수와 제보 경로가 현재도 나타나는지 다시 엽니다. GitHub 이슈 작성 화면을 여는 것과 이슈 접수는 구분합니다.
- 프리릴리스 노트: 정식 추천판을 같은 문단에서 명시하고, 실기 미검증·제한을 제목과 본문에서 감추지 않습니다.
- GameYob 노트: 공개 v0.5.10 범위만 설명합니다. 미완료 SGB 기능과 실기 무선 시험을 보증하지 않습니다.

포털 링크는 실제 발행 URL을 확인한 뒤에만 연결합니다. 글 본문에 사용자 개인 경로, 관리자 링크·캡처, ROM·세이브·BIOS를 넣지 않습니다.

## 이번 실행 결과

Chrome 연결을 복구한 뒤 기존 `/3`을 같은 URL·공개일·원문을 유지하며 갱신하고, 신규 개발노트 7편을 `/4`–`/10`에 각각 공개했습니다. 각 공개 페이지에서 제목·주요 본문·근거 링크를 확인하고 실제 본문 SHA-256을 metadata와 `post-map.json`에 기록했습니다. `/2`는 `no_change`입니다.

다음 순서는 이후 추가 갱신 시 적용할 안전 절차입니다.

1. 관리 화면에서 대상 블로그와 공개 `/2`, `/3`을 확인합니다. `/2`는 그대로 둡니다. 게시 직전에 `/3`의 현재 편집기 원문을 다시 읽고 별도 gitignore 로컬 백업 `qa-artifacts/blog-backups/3.html`과 대조합니다. 차이가 있으면 작업을 중단하고, 최신 원문을 별도 백업한 뒤 변경 내용을 검토합니다. 기존 글을 삭제하거나 전체 덮어쓰지 말고, 확인된 필요 구간만 안전하게 병합합니다. 무단으로 백업 원문을 복원해 현재 편집 내용을 덮어쓰지 않습니다.
2. 대조를 마친 `/3`에는 날짜가 붙은 최신 버전 HTML 조각만 추가합니다. 기존 URL·발행일·댓글·본문 기록을 보존합니다. 저장 전 두 웹 패처에 ND2 v1.0과 ND3 v1.2가 실제 선택되는지 확인합니다.
3. 신규 개발노트 7편은 각 metadata의 `categoryProposal`과 `tags`를 사용해 글별로 작성·미리보기·저장·게시합니다. 프리릴리스 글은 정식 권장판과 미검증 상태를 함께 확인합니다.
4. 저장/발행 후 실제 페이지를 다시 열어 제목·본문·링크를 확인합니다. 기존 `/3`은 같은 URL을 유지하고, 신규 글은 실제 생성된 URL만 `post-map.json`과 metadata에 기록합니다. 확인한 뒤 `postStatus`, 본문 fingerprint, `publishedThroughCommit`을 갱신합니다. 발행이 확인되지 않은 글은 URL이나 공개 상태를 임의로 채우지 않습니다.
