# [기술자료] 테스트 통과는 어디까지 말해 주나 — 자동 검사와 실기 확인을 구분하기

프로젝트의 “테스트 통과”는 한 가지 의미가 아닙니다. 작은 함수 테스트, 합성 입력으로 한 경계 검사, PC 에뮬레이터에서의 부팅 확인, 실제 대상 기기의 동작 확인은 서로 다른 환경에서 서로 다른 질문에 답합니다. 숫자가 큰 테스트 묶음이라도 그 숫자만으로 실제 기기 호환이 증명되지는 않습니다.

## 검증 결과를 읽는 간단한 지도

아래 단계는 우열 순위가 아니라 증거 종류입니다. 같은 프로젝트라도 기능에 따라 여러 종류가 필요할 수 있고, 한 단계가 다른 단계를 자동으로 대신하지 않습니다.

| 증거 종류 | 예를 들어 답할 수 있는 질문 | 단독으로는 답할 수 없는 질문 |
| --- | --- | --- |
| 단위·합성 테스트 | 주어진 작은 입력에서 함수가 기대한 값을 냈는가? 잘못된 입력을 거부하는가? | 실제 게임 파일과 모든 예외 입력에서 동작하는가? |
| 빌드·정적 검사 | 지정된 구성으로 소스가 컴파일·패키징되는가? | 실행 중 시간 순서나 기기별 I/O가 맞는가? |
| 호스트·참조 에뮬레이터 smoke | 특정 실행 파일이 부팅하거나 특정 화면·파일 선택 흐름을 통과하는가? | 실기 그래픽·오디오·저장장치·속도까지 같은가? |
| PC 게임 실행·제한 플레이 | 기록한 게임·경로에서 시작, 저장, 메뉴 등 관찰 항목이 동작했는가? | 다른 게임·모든 분기·모든 저장 경로가 맞는가? |
| 실제 대상 기기 검사 | 특정 기기·카드·설정에서 기록한 절차가 통과했는가? | 다른 하드웨어 조합과 전 조건에서 일반적으로 보장되는가? |

예를 들어 공개 GBARunner3 시험판은 ARM7/ARM9 사이 오류 전달과 논리적 4KiB 경계의 저장 서명 탐색을 자동 검사했다고 기록하지만, 물리 SD 오류·카드 제거·전원 차단 뒤의 복구를 실기에서 검증했다고 말하지 않습니다. 테스트는 저장 경로의 일부 논리를 살폈지만 실제 카드 고장 시험은 별개라는 뜻입니다.

NitroSwan 시험판의 공개 기록은 Python·호스트 C·빌드·합성 ARM 검사를 비롯해 melonDS 부팅과 파일 브라우저 smoke를 구분하고, 실제 DSpico 기기나 전투 장면·오디오·세이브 왕복을 확인하지 않은 범위를 따로 적습니다. 이때 “부팅 확인”을 “모든 게임이 정상 동작”으로 바꿔 읽으면 안 됩니다.

한글 패치 검증도 비슷합니다. 공개된 PC 에뮬레이터에서 신규 게임 저장과 다시 불러오기를 확인한 기록은 해당 버전과 에뮬레이터에서 수행한 경로의 근거입니다. 자연 진행 전체, 모든 분기, 실제 하드웨어 검사를 의미하지 않는다면 그 한계를 함께 읽어야 합니다.

## 로그와 성공률을 해석할 때

테스트 개수는 측정 단위와 범위가 같을 때만 비교할 수 있습니다. 80개의 합성 검사와 8개의 실기 시나리오는 숫자만 나란히 놓아 성능이나 신뢰도로 순위를 매길 수 없습니다. 실패 후 재시도, 테스트 간 겹침, 비활성 조건, 실행 환경도 결과의 의미를 바꿉니다. 기록이 구체적일수록 재현이 쉬워지지만, 기록이 상세하다고 검증 범위가 자동 확장되는 것은 아닙니다.

결과를 읽을 때는 다음 순서로 확인하면 과장된 결론을 피할 수 있습니다.

1. 무엇을 시험했는지 확인합니다: 대상 코드, 게임/파일 식별 정보, 기능과 입력 조건.
2. 어디서 실행했는지 확인합니다: 합성 fixture, 호스트 PC, 참조 에뮬레이터, 실제 대상 기기.
3. 무엇이 통과했는지 확인합니다: 빌드, 부팅, 메뉴, 첫 저장, 재시작 후 재로드 등 관찰 가능한 단위.
4. 무엇이 실행되지 않았는지 확인합니다: 자연 진행, 분기, 오디오, 제거·전원차단, 다른 기기 조합.
5. 보고서의 “통과”를 위 범위 안에서만 요약합니다. 미실행은 실패도 성공도 아닌 미확인입니다.

개발 노트와 릴리스 기록을 읽을 때는 “테스트가 통과했다”는 한 문장보다 테스트 환경·재현 경로·미검증 목록을 함께 확인하세요. 제보를 남길 때에도 프로젝트 버전, 기기/실행 환경, 재현 단계와 예상/실제 결과를 분리하면 유지관리자가 어느 증거 층부터 확인할지 결정하는 데 도움이 됩니다. ROM, BIOS, 세이브 파일은 공개 이슈에 올리지 마세요.
